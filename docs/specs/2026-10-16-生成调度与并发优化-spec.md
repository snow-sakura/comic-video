## 1. 背景与问题

端到端验证发现：结果"要么失败要么缺失"，根因是**调度层三处设计缺陷 + 两处配置失效**：

| # | 问题 | 证据（代码位置） |
|---|---|---|
| P1 | 并发配置是**摆设**：`QUEUE_DEFS.concurrency` / `WORKER_CONCURRENCY_*` / `config.worker_concurrency_*` 定义了但**无人消费**；worker 实际以 `--pool=solo` 单进程串行跑全部 5 队列 | `app/queue.py:24-46`、`app/core/config.py:193-197`、`scripts/start.sh:60-61`、`scripts/start-backend.sh:57-58` |
| P2 | **无跨集顺序控制**：`stage=video` 一次性把该集全部镜头入队，第 2 集可与第 1 集并行提交，无"上一集完成才进下一集"的闸门 | `app/api/projects_detail.py:1520-1579` |
| P3 | **视频 503 `queue_full` 直接判失败**：image 有 `_requeue_self` 延迟重入队，video 没有（provider 内 4 次退避 20/40/60/60s 耗尽即 FAILED）；实测 4 条视频 3 条 FAILED | `workers/tasks.py:295-313`（仅 image）、`app/providers/video.py:28-29,140-142` |
| P4 | **失败 error 为空**：`ConnectError('')` / `ConnectTimeout('')` 的 `str(e)` 为空串，UI 显示失败但无原因 | `workers/tasks.py:192,316,508` |
| P5 | **LLM 超时 300s < 实测响应 408s**，长剧本必触发网络错误重试，集数多时有整任务失败风险 | `app/providers/text.py:124` |
| P6 | **限流重试期间 UI 只显示"处理中"**，任务中心只见"16m7s 处理中"，无"限流等待重试"语义 | `workers/tasks.py:305-313`、前端 `ComposeWorkbench.tsx:366-400` |

**免费档限流事实**（决定调度策略）：
- Agnes 免费视频：1 次/分钟（`video.py:10,24`），并发 >1 必然 429/503
- Agnes 免费图片：实测持续 503 限流
- Agnes 付费视频：`agnes-video-2.5` 正价档，无 1/min 限制（`catalog.py:135-139`）

## 2. 目标 / 非目标

### 目标
- **G1 档位感知调度**：按当前生效模型的 `free`/`paid` 标签决定并发策略
  - 免费档 → 每队列**单任务串行**（一次只跑一个）
  - 付费档 → 每队列**多进程并行**
- **G2 按集顺序**：一集的 视频+配音+合成 **全部完成**，才允许进入下一集
- **G3 结果完整性**：限流/网络类瞬时错误自动重入队，不落 FAILED；失败必有可读原因
- **G4 前端可观测**：限流等待、失败原因、集顺序锁定态、并发档位 均在 UI 可见

### 非目标
- 不做跨项目全局调度公平性
- 不做付费档的费用预算熔断（`app/cost` 费用记录已存在，不在本次范围）
- 不改 5 队列拓扑与任务命名契约
- 不做 worker 热重载并发（本期"改档位需重启 worker"，见 D4）

## 3. 关键设计决策（需评审确认）

| # | 决策 | 推荐方案 | 备选 |
|---|---|---|---|
| **D1 档位判定** | 读 `provider_settings` 生效的 `text/image/video/tts` 的 model id → 查 `catalog.tags` 含 `free` 即免费；**任一关键队列用付费模型 → 该队列并行** | 备选：.env 新增 `SCHED_TIER=auto\|free\|paid` 强制覆盖 |
| **D2 并行实现** | **每队列起 N 个 solo worker 进程**（`-Q image -c` 不可用，solo 不支持并发），同队列 N 实例竞争消费 Redis 队列 → 天然并行；避免 `prefork` 在 macOS + `asyncio.run` 下的 fork 安全问题 | 备选：`--pool=concurrent --threads=N`（需验证 Celery 任务内 `asyncio.run` 线程隔离） |
| **D3 集间推进** | **自动连播**：一集全部完成后自动入队下一集（后端续排器触发） | 备选：仅顺序闸门，下一集手动点击 |
| **D4 并发数来源** | 免费=1；付费默认 `script=2, image=4, video=3, audio=4, compose=1`，`WORKER_CONCURRENCY_*` 可覆盖；启动脚本调用 `python -m app.batch_plan` 取 JSON | 设置页可视化调并发 → P2 迭代 |
| **D5 失败是否阻塞下一集** | **阻塞**：该集存在 FAILED 镜头则不推进，UI 显示"待重试"，用户可选"跳过该镜头继续" | 备选：自动跳过失败镜头 |

**并行与顺序的关系（必须明确）**：并行度只作用于**同一集内部**的镜头；**跨集始终串行**（D3 闸门优先级高于并行度）。

## 4. 变更详设

### B1 档位解析模块（新增 `app/scheduler/tier.py`）

```python
def get_tier(queue: str) -> Literal["free", "paid"]  # script|image|video|audio|compose
def get_concurrency_plan() -> dict[str, int]          # {queue: N}，免费恒为 1
```

- 数据源优先级：`SCHED_TIER` env 强制 > `provider_settings` 生效模型 > `.env` > 默认值
- 模型→档位：`app/providers/catalog.get_catalog()` 中 `tags` 含 `"free"` → free
- audio 档位看 `tts.engine`（`mimo`/`edge-tts`/`confucius4`/`voxcpm` 免费；`tokendance` 付费）
- 提供 CLI：`python -m app.batch_plan` 输出 `{"image": 1, "video": 3, ...}` 供启动脚本消费

**验收**：免费配置下计划全为 1；把 `video.model` 改为 `agnes-video-2.5` 后 video 计划变为 3。

### B2 启动脚本按计划起 worker 进程组（`scripts/start.sh`、`scripts/start-backend.sh`）

- 启动前执行 `PLAN=$(cd backend && .venv/bin/python -m app.batch_plan)`
- 每队列循环起 N 个独立进程：
  ```bash
  for i in $(seq 1 $N_image); do
    celery -A app.core.celery_app worker -Q image -l info --pool=solo -n "image@$HOSTNAME-$i" &
  done
  ```
- 日志分流到 `backend/logs/worker-<queue>-<i>.log`，便于定位
- cleanup 需回收全部子进程 PID

**验收**：免费配置 `pgrep -fl celery` 恰 5 进程（每队列 1）；付费配置 image=4 时为 8 进程。

### B3 视频限流自动重入队（`workers/tasks.py`）

- 抽象 `_requeue_self(queue, task_name, data, retry_n, countdown)`（当前硬编码 `image_task`，`tasks.py:341`）
- `_video_handler` 的 `except` 分支复用 image 的限流分支：识别 `_is_rate_limit_error` → 延迟重入队 + 刷 `updated_at` + 保持 PROCESSING
- 扩展 `_is_rate_limit_error` 关键词：`queue_full`、`限流`、`429`、`503`、`每分钟最多`、`重试耗尽`
- **免费档专属**：`video.py` 的 `_agn_wait_rate_limit()` 进程级闸门 `_agn_last_submit_at` 在多进程下失效；付费档本就无 1/min 限制 → 按 `get_tier("video")` 决定是否启用闸门，且付费档禁用（避免无谓等待）
- 保护已有防护：`recover_stuck_tasks` 以 `updated_at` 判卡死（`queue.py:172`），限流重入队已刷新 `updated_at`（`tasks.py:302`）→ 不会被误杀；**验收必须覆盖**

**验收**：Agnes 503 期间视频任务最终 DONE（自动重试成功）或重试耗尽后 FAILED **且 error 含 "queue_full" 原文**。

### B4 空错误消息兜底（`workers/tasks.py` + 新增 helper）

```python
def _err(e: BaseException) -> str:
    return str(e) or repr(e) or type(e).__name__
```

- 所有 `_mark_failed(db, task_id, str(e))` 改为 `_mark_failed(db, task_id, _err(e))`
- 覆盖点：`tasks.py:192,316,508,632` 等；`image/video/audio/compose/script` 五处理器全查
- `str(e)` 为空的场景：`httpx.ConnectError`/`ConnectTimeout`/`ReadTimeout`

**验收**：人为断网触发 ConnectTimeout，任务中心失败行显示 `ConnectTimeout('...')` 而非空白。

### B5 LLM 超时上调（`app/providers/text.py:124`）

- `timeout=300` → `timeout=600`（实测单次 408s，留 45% 余量）
- 同时核对 `image.py:56 timeout=180`（图片实测 13-16s，充足，不动）
- 加 `.env` 可覆盖：`TEXT_TIMEOUT_SEC`（默认 600）

**验收**：第1集剧本任务不再出现"网络错误第1次"重试日志。

### B6 按集顺序闸门 + 自动续排（核心）

**改动点：`app/api/projects_detail.py` stage 处理 + `workers/tasks.py` 完成回调**

1. **入队闸门**（`stage=video/voice/compose` 时）：
   - 新增 `_check_episode_gate(db, project_id, episode_number)`：
     - 若存在 `number < episode_number` 的集，其 shot 未全部 `video_path` + `voice_path`（有台词者）→ `409`，body 携带 `{"blockedBy": N, "reason": "第N集尚未完成"}`
   - 替换现有同集 409 逻辑（`projects_detail.py:1539-1540`）为跨集版本

2. **自动续排器**（任务 DONE 后触发）：
   - `_mark_done` 后调用 `_advance_pipeline(db, project_id, episode_number)`：
     - 判定本集完成：全部 shot `video_path` 非空 + （有台词的 shot `voice_path` 非空）+ compose `DONE`
     - 完成 → 找到下一集（`number+1`）→ 就绪 shot 入队（复用 stage=video 的入队逻辑，抽成 `_enqueue_stage(db, project_id, episode, stage)`）
     - `SCHED_AUTO_ADVANCE=false` 可关闭（D3 选自动连播时）
   - **失败阻塞**（D5）：本集存在 FAILED 的 GenTask → 不推进，UI 显示"待重试"；提供 `POST /projects/{id}/stage` 新增 `action: "skipFailed"` 显式跳过

3. **付费并行 × 集内**：付费档下同集 9 个 shot 的 image/video 任务并行消费（B2），但下一集仍被闸门挡住 → 满足 G1+G2

**验收**：两集项目点"生成视频"第 2 集 → 409 `blockedBy=1`；第 1 集合成 DONE 后第 2 集自动开始入队。

## 7. 验收方式（浏览器自动化，Playwright）

1. **免费档串行**：`SCHED_TIER=free` 启动 → 批量出图 → `pgrep -fl celery | grep image` 恰 1 进程；任务中心逐条 DONE，无并发 503 风暴
2. **付费档并行**：`SCHED_TIER=paid` 重启 → image 4 进程；9 图完成耗时显著低于免费档（记录前后对比）
3. **按集顺序**：两集项目，第 2 集"生成视频" → UI 显示"已锁定 · 第1集未完成" + 409；第 1 集合成完成后第 2 集**自动**开始（无需人工点击）
4. **限流可观测**：制造 503 → 任务中心显示"限流等待重试 第N次"，最终 DONE
5. **失败可读**：断网触发 → 失败行 `<details>` 展开含 `ConnectTimeout(...)` 原文
6. **回归**：四步全流程从建项目到成片导出再跑一遍，无 console error（favicon 除外已修）
